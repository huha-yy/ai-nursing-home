# 公网体验环境复刻手册（frp 内网穿透）

> **目的**：让部署在客户/院内内网一体机上的项目，能被公网上的客户直接通过浏览器体验。
> 本手册沉淀自 2026-08-15 上线的 eldcare.cn 项目实操（JOURNAL 08-21 公网访问架构篇），
> 其他同事或 AI 可按步骤为**新客户/新项目**复刻同样的公网入口。
>
> 实例参数以本文「附录 A：本项目实参表」为准；复刻新项目时逐项替换。

---

## 1. 架构总览

```
客户浏览器
   │  https://<子域>.eldcare.cn:8443
   ▼
腾讯云服务器（公网 IP，frps :7000 打洞 + :8443 按域名分流，TLS 在此终结）
   │  按 Host 域名路由到远端端口
   ├─ admin.eldcare.cn → 远端 19081 ──┐
   └─ chat.eldcare.cn  → 远端 19080 ──┤ frpc 隧道（反向连接，无需内网开入站端口）
                                      ▼
                         内网一体机 frpc（systemd 常驻）
                                      │ 转发到 127.0.0.1 对应端口
                                      ▼
                         本机 Caddy 反代层（:9080 / :9081，HTTP）
                                      │
                                      ▼
                         实际服务（dato-control 容器 / nursing-erp 宿主机进程）
```

**为什么这样设计**：
- 内网机器没有公网 IP、不能开放入站端口 → 用 **frp 反向隧道**（frpc 主动连云端 frps，出站连接，绕过 NAT）
- 云端 :8443 一个端口按 **Host 域名分流**多个服务 → 客户只需记一套「https://域名:8443」
- TLS 只在云端终结一张 **通配符证书** `*.eldcare.cn` → 加一个子域名**不需要**新申请证书
- 内网侧再垫一层 **Caddy 反代**（而不是 frpc 直连应用）→ 应用端口统一收敛、可加静态页路由、应用重启不牵动隧道

## 2. 前置条件清单

| # | 条件 | 说明 |
|---|---|---|
| 1 | 一台有公网 IP 的云服务器 | 本项目：腾讯云 43.137.7.133 |
| 2 | 一个可控 DNS 的域名 | 本项目：eldcare.cn；需能加 A 记录 |
| 3 | 通配符 TLS 证书 | 本项目：ZeroSSL `*.eldcare.cn`，**注意有效期，续期是日历事项**（当前张到期 2026-11-11） |
| 4 | 内网机能出公网 | frpc 只需出站 TCP 到云端 :7000 |
| 5 | 内网机上的服务已在本机可访问 | curl 本机端口先通，再上隧道 |

## 3. 复刻步骤

### 阶段一：云端（frps + 证书 + 域名分流）

> 云端配置**不在本仓库**，需登录云服务器操作。本项目实测形态如下，新环境照此核对。

1. 安装 frps（本项目 frpc/frps 版本 **0.61.1**），监听 `:7000` 作为打洞端口，配 auth token
2. `:8443` 上按 Host/SNI 分流：`<子域A>` → 本机 19080，`<子域B>` → 本机 19081（云端是
   frps vhost 或前置 Nginx/Caddy 按 Host 转发到 frp 远端端口，以服务器实际配置为准）
3. `:8443` 挂通配符证书（证书+私钥放云端，内网侧全程 HTTP）
4. 防火墙/安全组放行 `:7000`（仅限内网机 IP 更佳）和 `:8443`（公网全开）
5. **不要**在 443 配 vhost（本项目未配，裸域名访问必然失败，属预期）

验证：云端 `systemctl status frps`；安全组规则截图留档。

### 阶段二：DNS

给每个服务加一条 A 记录，全部指向云服务器公网 IP：

```
chat.eldcare.cn   A  43.137.7.133
admin.eldcare.cn  A  43.137.7.133
```

验证：`dig +short <子域>.eldcare.cn` 返回云端 IP。

### 阶段三：内网侧（Caddy 反代层 + frpc）

**3.1 Caddy 站点块**（`infra/Caddyfile`，每个服务一个端口，明文 HTTP）：

```caddyfile
# <子域> 入口（云端 frps :19xxx → frpc → 此端口）
:9080 {
    # 可选：对外宣传单页 /intro/
    @pitch path /intro /intro/*
    handle @pitch {
        encode zstd gzip
        root * /srv/pitch
        file_server
    }
    handle {
        reverse_proxy dato-control:8080 {
            header_up -X-Forwarded-Proto
            header_up X-Forwarded-Proto https   # TLS 在云端终结，手动补 https 头
        }
    }
}

:9081 {
    handle {
        reverse_proxy 172.19.0.1:8765 {        # 宿主机进程用网关 IP；容器用服务名
            header_up X-Forwarded-For {remote_host}
        }
    }
}
```

要点：
- 反代目标写 `172.19.0.1:<宿主机端口>`（docker 网关）或 `容器名:容器端口`
- **Caddyfile 改完必须 force-recreate**（单文件 bind-mount，编辑器替换 inode 后容器内
  仍是旧文件，`caddy reload` 无效）：
  ```bash
  cd infra && docker compose -p dato -f docker-compose.yml up -d --force-recreate dato-caddy
  ```
  ⚠️ `-p dato` 必须带（从 infra 目录跑），否则容器名冲突

**3.2 frpc 客户端**（`/etc/frp/frpc.toml`）：

```toml
serverAddr = "43.137.7.133"
serverPort = 7000
auth.method = "token"
auth.token = "<TOKEN-见密钥管理>"

[[proxies]]
name = "ai-chat"
type = "tcp"
localIP = "127.0.0.1"
localPort = 9080          # 对应本机 Caddy 块
remotePort = 19080        # 云端分流目标端口

[[proxies]]
name = "erp"
type = "tcp"
localIP = "127.0.0.1"
localPort = 9081
remotePort = 19081
```

**3.3 systemd 常驻**（`/etc/systemd/system/frpc.service`）：

```ini
[Unit]
Description=frp client
After=network.target

[Service]
ExecStart=/usr/local/bin/frpc -c /etc/frp/frpc.toml
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now frpc
```

### 阶段四：应用侧放行域名（不做必 400/403）

| 应用 | 配置位置 | 内容 |
|---|---|---|
| Django（nursing-erp） | `nursing-erp/.env`（gitignored） | `ALLOWED_HOSTS=admin.eldcare.cn,...`；`CSRF_TRUSTED_ORIGINS=https://admin.eldcare.cn:8443` |
| FastAPI（dato-control） | `infra/.env` | `DL_CONTROL_SITE_HOST=chat.eldcare.cn` |

改完重启对应进程/容器。

### 阶段五：验证清单（全部要绿）

```bash
# 1. 隧道活着
systemctl status frpc
# 2. 公网域名解析正确
dig +short chat.eldcare.cn            # → 云端 IP
# 3. 证书有效（云端终结层）
openssl s_client -connect chat.eldcare.cn:8443 -servername chat.eldcare.cn </dev/null \
  | openssl x509 -noout -issuer -dates
# 4. 公网入口响应（服务器本机测，务必 --noproxy）
curl -sk --noproxy '*' -o /dev/null -w '%{http_code}\n' https://chat.eldcare.cn:8443/chat
# 5. 浏览器（外网手机热点）打开公网 URL，登录页能渲染、能登录
```

## 4. 新增一个客户项目（照抄模板）

以「给 huha-crm（:8766）开公网入口 crm.eldcare.cn:8443」为例：

1. DNS：`crm A 43.137.7.133`
2. 云端：`:8443` 分流加一条 `crm.eldcare.cn → 远端 19082`（通配符证书无需动）
3. 本机 Caddyfile 加块：`:9082 { reverse_proxy 172.19.0.1:8766 }` → force-recreate dato-caddy
4. `/etc/frp/frpc.toml` 加 `[[proxies]] name="crm" localPort=9082 remotePort=19082` → `sudo systemctl restart frpc`
5. 应用侧：Django 加 ALLOWED_HOSTS/CSRF_TRUSTED_ORIGINS；FastAPI 加 SITE_HOST
6. 跑阶段五验证清单

## 5. 安全加固（公网暴露后必做，不可跳过）

暴露公网 = 全互联网可达。本项目踩过的真实教训：

- **API 认证**：ERP `/api/` 曾匿名裸奔，老人 PII 可被任意拉取（curl 实测）。加固方式：
  API key（机器调用，`X-API-Key` 常量时间比较）+ session（浏览器）双认证，**未配 key
  时 fail-closed**，绝不退化为无认证。详见 `nursing_erp/api_auth.py` 与 JOURNAL 08-21 篇
- 页面视图加 `@login_required`，未登录跳登录页
- 登录接口限流（本项目：15 分钟错 5 次锁，Redis key `login_fail:*`）
- 应用密码一律非弱密码；演示账号密码不要写进本文档
- 云端 `:7000` 收紧到内网机 IP 白名单（如果 frps 支持 proxy 白名单则更好）

## 6. 排障手册（按命中率排序）

| 症状 | 第一怀疑 | 处理 |
|---|---|---|
| 用户「打不开/对方关闭了连接」 | **用户本机 Clash 等代理**（8443 非常规端口走代理节点常不通，报错文案和 443 被掐一模一样） | 让用户关代理直连；服务器侧 `curl -sk --noproxy '*'` 双绿即证明服务端无恙 |
| 直连 `http://<子域>:19080` 返回 502 | 这不是有效入口 | 必须走 `:8443` 域名分流 |
| 裸域名（无 :8443）打不开 | 云端 443 未配 vhost | 属预期；入口永远带 `:8443` |
| 公网 ERP 502 | nursing-erp 是**宿主机进程**，挂了就 502 | `systemctl --user status nursing-erp.service` 拉起 |
| 全部 502 | frpc 掉线 | `sudo systemctl restart frpc` |
| 改了 Caddyfile 不生效 | 单文件 bind-mount inode 坑 | force-recreate dato-caddy（带 `-p dato`），`caddy reload` 无效 |
| Django 报 400 Bad Request | ALLOWED_HOSTS 没放行域名 | 补 `.env` 后重启进程 |
| 表单提交 403 CSRF | CSRF_TRUSTED_ORIGINS 没带 `https://<域名>:8443` | 同上 |
| 证书告警 | 通配符证书过期 | 云端续期（ZeroSSL/ACME），日历提前 2 周提醒 |

## 7. 密钥与证书管理

- frp auth token：内网侧在 `/etc/frp/frpc.toml`，云端在 frps 配置——**永不入 git**
- 各应用 API key：`nursing-erp/.env`、`infra/.env`（均 gitignored）
- 通配符证书 `*.eldcare.cn`（ZeroSSL ECC）：**只在云端**，内网侧无证书文件。
  当前张 `notAfter=2026-11-11`——**续期责任在持云服务器账号的人**，建议设日历
